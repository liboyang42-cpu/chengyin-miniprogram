## 3. 测试数据约定

| 项 | 约定值 | 说明 |
|---|---|---|
| 会话 token | `authorization=e2e-dev-token` | mock 会话,绕过真登录 |
| 测试用户 | `user_id=999001` `nickname=E2E测试号` `role=player` | 玩家态;核销流程临时切 `user_type=2/role=merchant` |
| 报名活动 | `activityId=8001` `ticketId=55` `票价 28.00` | 造受控下单态 |
| 支付参数 | `timeStamp/nonceStr/package/signType/paySign` 全为固定桩值 | 断言 orderData→requestPayment 透传 |
| 票券二维码 | `{"type":"activity","code":"VER-ABC-1"}` | 验票路由 |
| 优惠券二维码 | `{"type":"coupon","code":"CP-999"}` | 核销路由 |
| 非法二维码 | `not-a-json` | 负控:应不发请求 |
| 注销验证码 | `654321`(放行)/ 空(拦截) | 门禁断言 |
| 幂等键 | 建单 `req_*`、注销 `deregister-*` | 断言存在即可,值随机 |

> 独立测试账号 / 测试商户 / 平台白名单:接入真后端沙箱时由用户按 D-08「你的配合」提供。

## 4. 缺陷分级(defect grading)

| 级别 | 判定 | 处置 |
|---|---|---|
| **BLOCKER** | 核心链路走不通 / 资损 / 崩溃白屏 / 支付参数错 / 门禁失效 | 阻断发布,立即修 |
| **MAJOR** | 主流程可用但有功能缺陷 / 载荷字段错 / 状态机不对 | 发布前修 |
| **MINOR** | 边角提示 / 文案 / 非关键字段 | 记录,可迭代 |
| BOUNDARY | 物理边界(需真机/沙箱/部署),非缺陷 | 部署后真机回归 |

## 7. 断言与负控说明(为什么"全绿"有意义)

脚本内置负控(已知错输入必须被判 FAIL):
- 核销:非法二维码 → 断言**不发起**核销请求;
- 注销:未勾选确认 / 无验证码 → 断言 apply **被门禁拦截、不提交**;
- 官方活动 CTA:`roamEnabled=false` → 断言 `_cta` 回 `explore` 而非恒返 `roam`。

若这些负控项跑成 PASS(即错误输入没被拦住),说明校验器是橡皮图章,结果无效。
